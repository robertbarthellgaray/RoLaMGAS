# RoLaMGAS release workflow

The user must try local candidate builds before new builds are uploaded or deployed.
Prepare and test a local executable first, give the user its path, and wait for
explicit approval after their trial before uploading binaries, publishing releases,
pushing release tags, or triggering remote native-build workflows.
Do not treat approval of an earlier release as approval of a new build.
Keep existing released binaries unchanged while a local build awaits feedback.
